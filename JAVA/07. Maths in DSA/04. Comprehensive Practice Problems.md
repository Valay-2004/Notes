## 1. Sum of Divisors of All Numbers from 1 to N

**Problem:** Given an integer $n$, find the sum of divisors of all numbers from $1$ to $n$. Mathematically, calculate:
$$F(n) = \sum_{i=1}^n \sigma_1(i)$$
Where $\sigma_1(i)$ represents the sum of all positive divisors of $i$. Implement an algorithm that runs in $O(\sqrt{n})$ time.

```java
public class SumOfDivisors {
    public static long sumOfDivisors(int n) {
        long totalSum = 0;
        int i = 1;

        while (i <= n) {
            int quotient = n / i;
            // Find the last index j where n / j gives the same quotient
            int j = n / quotient;

            // Sum of integers from i to j: (j - i + 1) * (i + j) / 2
            long termCount = j - i + 1;
            long termSum = (long) (i + j) * termCount / 2;

            totalSum += quotient * termSum;

            // Move to the next block
            i = j + 1;
        }

        return totalSum;
    }

    public static void main(String[] args) {
        int n = 4;
        System.out.println("Sum of divisors from 1 to " + n + " is: " + sumOfDivisors(n));
        // Explanation for n = 4:
        // Divisors of 1: [1] -> sum = 1
        // Divisors of 2: [1, 2] -> sum = 3
        // Divisors of 3: [1, 3] -> sum = 4
        // Divisors of 4: [1, 2, 4] -> sum = 7
        // Total sum = 1 + 3 + 4 + 7 = 15.
    }
}
```

> [!INFO] Detailed Explanation
>
> 1. **Reordering the Summation:** In the naive approach, we find the divisors for each number. Instead, we can count the contribution of each divisor $d$ to the total sum. A divisor $d$ divides exactly $\lfloor n / d \rfloor$ numbers in the range $[1, n]$. Thus, its total contribution to the sum is $d \times \lfloor n / d \rfloor$.
>    $$F(n) = \sum_{d=1}^n d \times \lfloor \frac{n}{d} \rfloor$$
> 2. **Square Root Decomposition (Range Query):** The value of $\lfloor n / d \rfloor$ changes in steps. For a given $i$, the quotient $q = \lfloor n / i \rfloor$ remains constant for all $d$ in the range $[i, j]$, where $j = \lfloor n / q \rfloor$.
> 3. **Arithmetic Progression:** Rather than adding $d \times q$ one by one, we factor out $q$ and sum the numbers in the range $[i, j]$:
>    $$\sum_{d=i}^j d \times q = q \times \sum_{d=i}^j d = q \times \frac{(j - i + 1)(i + j)}{2}$$
> 4. **Sub-linear complexity:** Since $\lfloor n / d \rfloor$ has at most $2\sqrt{n}$ distinct values, the loop runs in $O(\sqrt{n})$ steps.

- **Time Complexity:** $O(\sqrt{n})$
- **Space Complexity:** $O(1)$

## 2. Count Unique Binary Search Trees (Catalan Numbers)

**Problem:** Given an integer $n$, find the number of structurally unique Binary Search Trees (BSTs) that can be formed using keys from $1$ to $n$.

```java
public class UniqueBSTs {

    // Approach 1: Dynamic Programming - O(n^2) time, O(n) space
    public static int numTreesDP(int n) {
        int[] dp = new int[n + 1];
        dp[0] = 1;
        dp[1] = 1;

        for (int i = 2; i <= n; i++) {
            for (int j = 1; j <= i; j++) {
                dp[i] += dp[j - 1] * dp[i - j];
            }
        }
        return dp[n];
    }

    // Approach 2: Combinatorial Formula - O(n) time, O(1) space
    public static long numTreesFormula(int n) {
        // C_n = (2n)! / ((n+1)! * n!) = Product_{i=1..n} (n + i) / i
        long catalan = 1;
        for (int i = 1; i <= n; i++) {
            catalan = catalan * (n + i) / i;
        }
        return catalan / (n + 1);
    }

    public static void main(String[] args) {
        int n = 3;
        System.out.println("Unique BSTs for n = " + n + " (DP): " + numTreesDP(n));         // Output: 5
        System.out.println("Unique BSTs for n = " + n + " (Formula): " + numTreesFormula(n)); // Output: 5
    }
}
```

> [!INFO] Detailed Explanation
>
> 1. **Recursive Formulation:** To construct a BST with $n$ nodes, we can choose any node $j$ ($1 \le j \le n$) as the root. The left subtree will contain $j-1$ nodes (keys $1 \dots j-1$), and the right subtree will contain $n-j$ nodes (keys $j+1 \dots n$).
> 2. **Recurrence Relation:** Let $G(n)$ be the number of unique BSTs.
>    $$G(n) = \sum_{j=1}^n G(j-1) \times G(n-j)$$
>    This matches the definition of the Catalan number sequence: $C_0 = 1, C_n = \sum_{i=0}^{n-1} C_i C_{n-1-i}$.
> 3. **Combinatorial Optimization:** The formula for the $n$-th Catalan number is:
>    $$C_n = \frac{1}{n+1} \binom{2n}{n}$$
>    We can compute this in a single loop by maintaining intermediate products to prevent integer overflow.

- **Time Complexity:** $O(n^2)$ for the DP approach; $O(n)$ for the combinatorial approach.
- **Space Complexity:** $O(n)$ for the DP approach; $O(1)$ for the combinatorial approach.

## 3. Find Two Unique Numbers in a Duplicate Array

**Problem:** Given an array of integers `nums` where every element appears exactly twice except for two elements which appear only once, find the two unique elements. Solve this in $O(n)$ time and $O(1)$ auxiliary space.

```java
public class SingleNumberIII {
    public static int[] getTwoUniqueNumbers(int[] nums) {
        int xorSum = 0;
        for (int num : nums) {
            xorSum ^= num;
        }

        // xorSum now holds (x ^ y), where x and y are the two unique numbers.
        // Get the lowest set bit (rightmost 1-bit) in xorSum.
        int lowestSetBit = xorSum & -xorSum;

        int x = 0;
        int y = 0;
        for (int num : nums) {
            if ((num & lowestSetBit) != 0) {
                x ^= num; // XOR group with set bit
            } else {
                y ^= num; // XOR group with unset bit
            }
        }

        return new int[]{x, y};
    }

    public static void main(String[] args) {
        int[] nums = {1, 2, 1, 3, 2, 5};
        int[] result = getTwoUniqueNumbers(nums);
        System.out.println("The two unique numbers are: " + result[0] + " and " + result[1]);
        // Output: 3 and 5 (order may vary)
    }
}
```

> [!INFO] Detailed Explanation
>
> 1. **XOR Cancellation:** XORing a number with itself cancels it out ($a \oplus a = 0$). XORing all elements together results in `xorSum = x ^ y`, where $x$ and $y$ are the unique elements.
> 2. **Differentiating bit:** Since $x \neq y$, `xorSum` must have at least one bit set to `1`. The expression `xorSum & -xorSum` extracts the rightmost set bit using 2's complement properties.
> 3. **Partitioning:** We partition the array into two groups based on whether this bit is set. $x$ and $y$ will fall into separate groups. All duplicates will also be partitioned, but since they appear in pairs, they cancel out within their respective groups, leaving only $x$ and $y$.

- **Time Complexity:** $O(n)$ — requires two passes over the array.
- **Space Complexity:** $O(1)$ auxiliary space.

## 4. Josephus Problem (Recursive Elimination)

**Problem:** There are $n$ people standing in a circle waiting to be eliminated. Starting from the first person, we count and eliminate every $k$-th person. The counting continues clockwise around the circle. Find the 1-indexed position of the last remaining survivor.

```java
public class JosephusProblem {

    // Iterative approach: O(n) time, O(1) space
    public static int findSurvivor(int n, int k) {
        int survivorPos = 0; // 0-indexed base case for 1 person

        for (int i = 2; i <= n; i++) {
            survivorPos = (survivorPos + k) % i;
        }

        return survivorPos + 1; // Convert to 1-indexed
    }

    public static void main(String[] args) {
        int n = 5, k = 2;
        System.out.println("The survivor position for n=" + n + ", k=" + k + " is: " + findSurvivor(n, k));
        // Output: 3
    }
}
```

> [!INFO] Detailed Explanation
>
> 1. **Base Case:** If there is only $1$ person, their position is $0$ (in 0-indexed terms).
> 2. **Recursive Transition:** When we eliminate the $k$-th person, the remaining circle has $n-1$ people. The indices shift by $k$ positions. Thus, the survivor's position in the original circle of size $n$ is related to their position in the circle of size $n-1$ by:
>    $$J(n, k) = (J(n-1, k) + k) \bmod n$$
> 3. **Iterative Build:** We build the solution bottom-up from $i = 2$ to $n$ to avoid recursion stack overflow.

- **Time Complexity:** $O(n)$
- **Space Complexity:** $O(1)$

## 5. Prime Sum (Goldbach's Conjecture Check)

**Problem:** According to Goldbach's Conjecture, every even integer greater than 2 can be expressed as the sum of two prime numbers. Given an even integer $n$ ($n > 2$), find a pair of prime numbers $(p_1, p_2)$ such that $p_1 + p_2 = n$. If multiple pairs exist, return the pair that minimizes $p_1$.

```java
import java.util.*;

public class PrimeSum {
    public static int[] findPrimePair(int n) {
        if (n <= 2 || n % 2 != 0) {
            return new int[0];
        }

        // Sieve up to n
        boolean[] isPrime = new boolean[n + 1];
        Arrays.fill(isPrime, true);
        isPrime[0] = isPrime[1] = false;

        for (int i = 2; i * i <= n; i++) {
            if (isPrime[i]) {
                for (int j = i * i; j <= n; j += i) {
                    isPrime[j] = false;
                }
            }
        }

        // Find the pair
        for (int i = 2; i <= n / 2; i++) {
            if (isPrime[i] && isPrime[n - i]) {
                return new int[]{i, n - i};
            }
        }

        return new int[0];
    }

    public static void main(String[] args) {
        int n = 10;
        int[] pair = findPrimePair(n);
        if (pair.length == 2) {
            System.out.println(n + " = " + pair[0] + " + " + pair[1]);
            // Output: 10 = 3 + 7 (instead of 5 + 5 because 3 is smaller than 5)
        }
    }
}
```

> [!INFO] Detailed Explanation
>
> 1. **Generating Primes:** We use a Sieve of Eratosthenes to precompute all prime numbers up to $n$ in $O(n \log \log n)$ time.
> 2. **Complement Search:** If $i$ is prime, we check if $n - i$ is also prime.
> 3. **Minimizing $p_1$:** Since we iterate $i$ starting from 2 upwards, the first valid pair we encounter will naturally minimize the first element.

- **Time Complexity:** $O(n \log \log n)$ due to the Sieve.
- **Space Complexity:** $O(n)$ for the sieve array.

## 6. Super Pow (Generalized Euler's Totient Theorem)

**Problem:** Calculate $a^b \bmod 1337$ where $b$ is an extremely large positive integer passed as an array of digits. Handle cases where $\gcd(a, 1337) \neq 1$.

```java
public class SuperPow {
    private static final int MOD = 1337;
    // phi(1337) = phi(7) * phi(191) = 6 * 190 = 1140
    private static final int PHI_MOD = 1140;

    public static int superPow(int a, int[] b) {
        a %= MOD;
        if (a == 0) return 0;

        // Calculate b % PHI_MOD
        int reducedExponent = 0;
        boolean isGreaterOrEqual = false;

        for (int digit : b) {
            reducedExponent = reducedExponent * 10 + digit;
            if (reducedExponent >= PHI_MOD) {
                isGreaterOrEqual = true;
                reducedExponent %= PHI_MOD;
            }
        }

        // If exponent >= phi(m), we must add phi(m) to the exponent
        if (isGreaterOrEqual) {
            reducedExponent += PHI_MOD;
        }

        return fastPower(a, reducedExponent, MOD);
    }

    private static int fastPower(int base, int exp, int mod) {
        int res = 1;
        base %= mod;
        while (exp > 0) {
            if ((exp & 1) != 0) {
                res = (res * base) % mod;
            }
            base = (base * base) % mod;
            exp >>= 1;
        }
        return res;
    }

    public static void main(String[] args) {
        int a = 2;
        int[] b = {1, 0}; // 2^10
        System.out.println("2^10 % 1337 = " + superPow(a, b));
        // Output: 1024
    }
}
```

> [!INFO] Detailed Explanation
>
> 1. **Euler's Totient Theorem:** If $a$ and $m$ are coprime, then $a^{\phi(m)} \equiv 1 \pmod m$. This allows us to reduce any large exponent $b$ to $b \bmod \phi(m)$.
> 2. **Coprime Limitation:** If $a$ and $m$ are _not_ coprime (e.g. $a$ shares factors with $1337$, which can happen since $1337 = 7 \times 191$), the simple modulo reduction fails.
> 3. **Generalized Euler's Theorem:** For any $a$ and $m$ (coprime or not):
>    $$a^b \equiv a^{b \bmod \phi(m) + \phi(m)} \pmod m \quad \text{for } b \ge \phi(m)$$
>    Hence, if the digit array value $b \ge \phi(1337)$, the reduced exponent is $(b \bmod 1140) + 1140$. If $b < \phi(1337)$, we can use the original value of $b$ directly.

- **Time Complexity:** $O(N)$ where $N$ is the number of digits in array $b$.
- **Space Complexity:** $O(1)$.
