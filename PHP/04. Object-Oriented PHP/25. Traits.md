# Traits

## TL;DR

Because a PHP class can only extend one parent class, sharing helper methods across unrelated classes can feel awkward. A **trait** is a reusable bundle of methods and properties that any class can pull in with `use`.

> [!NOTE] Prerequisites: 22, 24
> New terms: trait, composition

> [!abstract] Core Idea
> Declare shared methods in a `trait` and copy them into any class with `use`, enabling horizontal **composition** without inheritance.
> Unlike Python's multiple inheritance or mixins, PHP traits are explicitly pasted into the class body at compile time so there is only one parent chain.

## Mental Model

Think of a `trait` as a stamp you can press onto any notebook page. Whether an item in your app is a `Book` or a `ReaderNote`, pressing the `HasTags` stamp (`use HasTags;`) gives both classes the exact same tagging methods without forcing them to share a parent class.

```mermaid
flowchart LR
    T["trait HasTags<br/>$tags, addTag(), tags()"] -->|"use HasTags;"| B["class Book"]
    T -->|"use HasTags;"| N["class ReaderNote"]
```

- A **trait** is a code-reuse block declared with `trait` that holds methods and properties for classes to include via `use`.

## Minimal Example

```php
<?php
trait HasTags
{
    private array $tags = [];

    public function addTag(string $tag): void
    {
        $this->tags[] = $tag;
    }

    public function tags(): array
    {
        return $this->tags;
    }
}

class Book
{
    use HasTags;

    public function __construct(public string $title) {}
}

$book = new Book('Dune');
$book->addTag('sci-fi');
print_r($book->tags());
```

Expected output:

```text
Array
(
    [0] => sci-fi
)
```

- `trait HasTags { ... }` defines a reusable bundle of `$tags`, `addTag()`, and `tags()`.
- `use HasTags;` inside `class Book` copies all members of `HasTags` into `Book` as if they were written there.
- `$book->addTag('sci-fi')` works directly on `$book`, and `$this->tags` inside the trait refers to `$book`'s own property.

## Compare

| Tool              | Keyword              | Purpose                                   | Can Be Instantiated? |
| ----------------- | -------------------- | ----------------------------------------- | -------------------- |
| Class Inheritance | `extends`            | Share & specialize one parent             | ✓ (if not abstract)  |
| Interface         | `implements`         | Enforce public method signatures          | ✗                    |
| Trait             | `use` (inside class) | Reuse concrete methods across any classes | ✗                    |

## ◈ Edge Case Analysis

✗ **Mistake 1:** Trying to create an object directly from a trait with `new HasTags()` throws a fatal `Error` because traits are only for mixing into classes.

```php
$t = new HasTags(); // Fatal error: Cannot instantiate trait HasTags
```

✓ **Fix:** Always `use` the trait inside a `class` and instantiate that class instead.

```php
$book = new Book('Dune');
```

✗ **Mistake 2:** Using two traits in the same class that both define a method with the same name throws a fatal error unless you resolve the collision.

```php
class Book {
    use TraitA, TraitB; // Fatal error if both define format()
}
```

✓ **Fix:** Keep trait method names distinct, or pick the winner explicitly with `insteadof`.

```php
class Book {
    use TraitA, TraitB { TraitA::format insteadof TraitB; }
}
```

✗ **Mistake 3:** Declaring a property in a class with the same name as a trait property but a different type, visibility, or default value throws a fatal error.

```php
trait HasTags { private array $tags = []; }
class Book {
    use HasTags;
    public array $tags = []; // Fatal error: different visibility
}
```

✓ **Fix:** Let the trait own `$tags`, or match its exact visibility, type, and initial value if redeclared.

```php
class Book { use HasTags; }
```

## Try It

1. Write a `trait HasRating` with `private int $rating = 0;`, `setRating(int $stars): void`, and `rating(): int`.
2. Add `use HasRating;` to a `Book` class, set a rating of `5`, and echo it.

<details>
<summary>◈ View Solution</summary>

1. `HasRating` trait:

```php
<?php
trait HasRating
{
    private int $rating = 0;

    public function setRating(int $stars): void
    {
        $this->rating = $stars;
    }

    public function rating(): int
    {
        return $this->rating;
    }
}
```

2. Using `HasRating` inside `Book`:

```php
class Book
{
    use HasRating;

    public function __construct(public string $title) {}
}

$b = new Book('Dune');
$b->setRating(5);
echo $b->rating() . PHP_EOL; // 5
```

</details>

## Topic Mastery Quiz

**Q1: How do you include a trait named `HasTags` inside `class Book`?**

- [ ] A) `class Book extends HasTags`
- [ ] B) `class Book implements HasTags`
- [ ] C) `use HasTags;` inside the `Book` class body
- [ ] D) `import HasTags;` at the top of the file

**Q2: What happens if you run `new HasTags()`?**

- [ ] A) It returns an empty object
- [ ] B) It throws a fatal `Error` because traits cannot be instantiated
- [ ] C) It creates a `stdClass`
- [ ] D) It returns `null`

**Q3: How many traits can a single PHP class include?**

- [ ] A) Only one
- [ ] B) Up to two
- [ ] C) Multiple traits separated by commas (`use A, B;`)
- [ ] D) None if the class already uses `extends`

**Q4: Inside a `HasTags` trait method, what does `$this` refer to?**

- [ ] A) The trait itself
- [ ] B) The object of the class using the trait
- [ ] C) Always `null`
- [ ] D) The parent class only

**Q5: What happens when a class uses two traits that both define `public function label(): string` without any conflict resolution?**

- [ ] A) The second trait silently overrides the first
- [ ] B) The first trait silently wins
- [ ] C) PHP throws a fatal error for the trait method collision
- [ ] D) Both methods run one after the other

**Q6: When a trait defines `private array $tags = [];`, what happens if the class using it also defines `public array $tags = [];`?**

- [ ] A) The class property overrides the trait property cleanly
- [ ] B) PHP throws a fatal error because the property visibility differs
- [ ] C) PHP creates two separate `$tags` properties
- [ ] D) `$tags` becomes `protected`

<details>
<summary>◈ View Answers & Explanations</summary>

1. **C** — Traits are included inside a class body with `use HasTags;`. `extends` (A) is for parent classes, `implements` (B) is for interfaces, and `import` (D) is not PHP syntax.
2. **B** — A trait is not a standalone class and cannot be instantiated with `new`, so `new HasTags()` throws a fatal `Error`. A, C, and D are false.
3. **C** — A class can include multiple traits using `use TraitA, TraitB;`, even if it also `extends` a parent class. A, B, and D are false.
4. **B** — Because traits are copied into the using class, `$this` refers to the live object instance of that class. A, C, and D are false.
5. **C** — PHP does not guess between colliding trait methods; it throws a fatal error unless you explicitly resolve the conflict with `insteadof` or `as`. A, B, and D do not happen.
6. **B** — A class cannot redeclare a trait's property with a different visibility, type, or initial value; doing so triggers a fatal error. A, C, and D are false.

</details>
