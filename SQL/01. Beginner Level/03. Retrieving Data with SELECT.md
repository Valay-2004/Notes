With an understanding of relational database structure from the previous chapter, we now focus on extracting data. The `SELECT` statement is the fundamental tool for querying information stored in tables.

## The Basic SELECT Statement

Relational databases store information neatly organized into tables, much like spreadsheets with rows and columns.
To retrieve any information for analysis or any other purpose from the database, SQL provides the `SELECT` statement/keyword. And `SELECT` is arguably the most used command in SQL. We can think of it as our primary tool for asking questions of your database.

The most basic form of the `SELECT` statement requires two main components:
1. `SELECT` : Followed by a list of column names which we want to retrieve.
2. `FROM` : Followed by the name of the table where those columns are present.

**Code Template:** 
```sql
SELECT column_name1, column_name2
FROM table_name;
```

> Code Templates are generated with in mind that you're using (`USE database_name`) the database in which the table resides.

> [!TIP] TIP
> SQL is case-insensitive meaning `SELECT`, `select`, `SeLeCt` will be treated the same, but mostly uppercase (`SELECT`) is used as common practice and is also good for readability.

In simpler terms, 
- `SELECT` is the keyword which can select any column inside the table 
- `FROM` is used to show which table is the columns are so that we can retrieve them using the `SELECT` command.
- `column_name*` are names of the columns which will be returned.
- `table_name` is name of the table from which we'll get our data.
- `;` semicolon at the end marks the end of the SQL statement. (Which is not strictly required but is a good practice to use `;` which also helps avoid `ambiguity` when multiple statements are used together).

**For Example:**
Imagine we have this simple table named `Product` having the given info.

| productid | product | category    | price |
| --------- | ------- | ----------- | ----- |
| 101       | Bottle  | Accessories | 10    |
| 102       | Tire    | Accessories | 15    |
| 103       | Socks   | Clothing    | 20    |
| 104       | Caps    | Clothing    | 25    |
| 105       | Gloves  | Clothing    | 30    |
Now if we want to fetch all the names of the product inside the `Products` table we can use the following.

```sql
select
	product
from
	products;
```

**Output:**

| product |
| ------- |
| Bottle  |
| Tire    |
| Socks   |
| Caps    |
| Gloves  |
As we are here I'll also like to add here `AS` command which treats a column name as according to our liking, like above we can see the column name is `product` and not `product_name` so we can use `AS` to change the name of the column on the returned result **NOT INSIDE THE TABLE**. 

> [!NOTE] NOTE
> `AS` Does not change the column name it only returns a different (which we gave) in the results.
> 

```sql
select
	product as product_name
from
	products;
```

**Output:**

|product_name|
|------------|
|Bottle|
|Tire|
|Socks|
|Caps|
|Gloves|
A more comprehensive information regarding `AS` will be seen in upcoming chapters. (I only added `AS` here to show the column name as `product_name`).

## Selecting Specific & All Columns

We can select all the columns from a table using `SELECT *` which can be useful for initial exploration, but if the table is **huge** the command can be said as ***inefficient and unnecessary***.

> In SQL, the `*` symbol is most commonly called the **asterisk**, but it is also frequently referred to as **"star"** or a **wildcard**.

To select specific columns from a table we can make use of the following:

```sql
-- Syntax 
SELECT col_name1, col_name2, col_name4
FROM table_name;
```

> [!NOTE] Comment in SQL
> If not already known
> We can use `--` to get a single line comment and for multi line comment we can make use of `/* */` 

The breakdown is similar to what we've learnt earlier..

**Example:**

```sql
select * 
from products;
```

When we make use of `*` wildcard we get all the info. available in the given table (here `products`).

|productid|product|category|price|
|---------|-------|--------|-----|
|101|Bottle|Accessories|10|
|102|Tire|Accessories|15|
|103|Socks|Clothing|20|
|104|Caps|Clothing|25|
|105|Gloves|Clothing|30|

And if we have to select only the `productid`, `product` and `price` column we can use the given:

```sql
select 
	productid, product, price 
from 
	products;
```

Output:

|productid|product|price|
|---------|-------|-----|
|101|Bottle|10|
|102|Tire|15|
|103|Socks|20|
|104|Caps|25|
|105|Gloves|30|
Thus we can see that we only got the three tables which we asked for.

Here the **order** of the **columns** will appear as the order we've given after the `SELECT` statement. If we wanted the `price` column to appear before the `productid`, we would simply put the `price` column in the front:

```sql
select 
	price, productid, product
from 
	products;
```

Which will result in:

|price|productid|product|
|-----|---------|-------|
|10|101|Bottle|
|15|102|Tire|
|20|103|Socks|
|25|104|Caps|
|30|105|Gloves|
> [!IMPORTANT] Commas
> - **Commas:** Remember to separate column names with commas. Forgetting a comma or adding an extra one where it doesn't belong is a common source of syntax errors.
> - **Case Sensitivity:** SQL keywords like `SELECT` and `FROM` are generally case-insensitive (so `select`, `Select`, or `SELECT` all work). However, the case sensitivity of table and column names (`Customers`, `first_name`) often depends on the specific database system (like PostgreSQL, MySQL, SQL Server) and its configuration. It's best practice to match the exact case used when the table was defined.


### Use cases for `SELECT *`

Using `SELECT *` is particularly useful in a few cases like:

 1. **Data Exploration and Ad-Hoc Troubleshooting:** When exploring an unfamiliar database or debugging issue, you may not known what columns exist. In this case using `LIMIT` statement is an excellent way to quickly preview the table's structure and the type of data it holds.
For Example: 
```sql
select 
	*
from
	products
limit
	3;
```

| productid | product | category    | price |
| --------- | ------- | ----------- | ----- |
| 101       | Bottle  | Accessories | 10    |
| 102       | Tire    | Accessories | 15    |
| 103       | Socks   | Clothing    | 20    |

> [!NOTE] `LIMIT`
> `LIMIT` statement -- as the name suggest it limits the result of the rows/records to the given number which is pretty good when dealing with an unfamiliar table.

 2. **Small Tables:** If a table only has a handful of columns, using `*` can be quicker than typing each column name (like in our `products` table which only has 4 columns and 5 rows).

 3. **Viewing Full Records**: When you need to see the complete record for specific rows (often used with a `WHERE` clause, we'll be learning this in upcoming notes).

### Important Best Practices

While `SELECT *` is convenient, it's often **not** recommended for use in production code, automated scripts, or complex analyses. Here’s why:

- **Performance:** Retrieving data you don't need consumes unnecessary resources. Asking for all columns when you only need two can significantly increase query time, network traffic, and server load, especially with tables containing many columns or rows.
- **Readability and Maintenance:** Explicitly listing the columns you need makes your query's intent clearer. `SELECT product_name, price FROM Products;` immediately tells the reader what data is being used. Furthermore, if the underlying table structure changes (e.g., a new column is added, or columns are reordered), `SELECT *` might return unexpected results or even break application code that expects a specific number or order of columns. Explicitly naming columns makes your query more resilient to such changes.
- **Ambiguity with Joins:** When you start combining data from multiple tables, using `SELECT *` can lead to ambiguity if tables share column names. Explicitly selecting `table_alias.column_name` prevents confusion.

## Using Aliases for Columns
We know that the `SELECT` statement is used to specify and retrieve columns from a table. Many times the original column names in a DB aren't ideal for a final report or analysis. Most of the names are simply not descriptive enough for an audience like (`prod_id`, `calculated_value_stream_1`, etc). This is where column aliases come in handy. 

An alias is a temporary name you assign to a column within the scope of a specific query
